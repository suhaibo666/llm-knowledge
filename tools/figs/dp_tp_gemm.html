切 B 的输入/收缩维（4d 维）匹配 H 的列切：GPU0 只有 H₁（前 2d 列）和 B₁（前 2d 行），算出的 Z₀ = H₁·B₁ 只是「沿 4d 求和」的前一半贡献；GPU1 算后一半 Z₁ = H₂·B₂。两片同形状、各自是部分和，谁都不是最终答案 —— 真正的 Z = Z₀ + Z₁，必须一次 all-reduce(sum) 把各卡部分和加起来，才与单卡等价。这就是「行切末尾必须通信」的根本原因。
一句话对照：列切产出的是不同的输出列 → 并排拼接（concat，无归约）；行切产出的是同形状的部分积 → 必须求和（reduce ⇒ all-reduce）。Megatron 故意排成「先列后行」：中间的 GeLU 和两 GEMM 衔接都免通信，把整个 MLP 的前向通信压到出口一次 all-reduce（反向对称地在入口一次）。
