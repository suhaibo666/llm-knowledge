## 一、模型架构

### 1.1 核心参数

| 参数 | 值 |
|------|-----|
| 总参数量 | 1.04T |
| 激活参数量 | 32B |
| 专家数量 | 384 |
| 每 Token 激活专家 | 8 |
| 稀疏度 | 48 |
| 预训练 Token | ~15T 图文混合 |
| 上下文窗口 | **256K** |

### 1.2 架构设计

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  MoonViT-3D  │───▶│  MLP Project │───▶│  Kimi K2     │
│  视觉编码器   │    │   投影层      │    │  MoE LLM     │
│  (原生分辨率) │    │              │    │  (1.04T)     │
└──────────────┘    └──────────────┘    └──────────────┘
       │                                    │
       ▼                                    ▼
  图像/视频                            文本/代码
  原生分辨率                            推理/工具
  输入处理                              调用能力
```

### 1.3 MoonViT-3D 视觉编码器

| 特性 | 说明 |
|------|------|
| **原生分辨率处理** | NaViT patch packing，支持可变分辨率 |
| **3D 时空编码** | 连续 4 帧视为时空体积，2D patches 联合展平 |
| **参数共享** | 图像和视频编码器完全共享 |
| **时间压缩** | 轻量级时间池化，**4× 时间压缩** |
| **初始化** | SigLIP-SO-400M |

```
输入图像/视频
    │
    ▼
┌──────────────┐
│ Patch n' Pack│  分割为 patches，展平为一维序列
└──────────────┘
    │
    ▼
┌──────────────┐
│ 共享注意力   │  同一注意力处理空间和时间维度
└──────────────┘
    │
    ▼
┌──────────────┐
│ 时间池化     │  4× 压缩（视频）
└──────────────┘
    │
    ▼
┌──────────────┐
│ MLP 投影器   │  连接到 K2 MoE 语言模型
└──────────────┘
```

## 三、视觉 Agent 能力

### 3.1 GUI 交互 (Computer Use)

| 基准 | K2.5 | Claude Opus 4.5 | GPT-5.2 |
|------|------|-----------------|---------|
| OSWorld-Verified | **63.3%** | 66.3% | 48.6% |
| WebArena | **58.9%** | 63.4% | - |

- 仅依赖 GUI 动作，不使用外部工具
- 支持 pyautogui 代码和专用函数
- 上下文包含最近 3 张历史截图

### 3.2 视觉工具使用

通过 IPython 实现程序化视觉操作：
- **迷宫求解**：二值化 + BFS 路径查找
- **饼图分析**：HSV 色彩分割 + 几何计算
- **找不同**：像素级差异检测 + 轮廓提取

### 3.3 Agent Swarm 并行智能体

**架构**：
- **可训练编排器 (Orchestrator)**：任务分解和子智能体调度
- **冻结子智能体 (Frozen Sub-agents)**：从固定中间策略实例化

**PARL 奖励函数**：
$$r_{\text{PARL}}(x,y) = \lambda_1 \cdot r_{\text{parallel}} + \lambda_2 \cdot r_{\text{finish}} + r_{\text{perf}}(x,y)$$

**关键步骤定义**：
$$\text{CriticalSteps} = \sum_{t=1}^{T} (S_{\text{main}}^{(t)} + \max_i S_{\text{sub},i}^{(t)})$$

**性能提升**：

| 基准 | 单智能体 | Agent Swarm | 提升 |
|------|---------|-------------|------|
| BrowseComp | 60.6% | **78.4%** | +17.8% |
| WideSearch | 72.7% | **79.0%** | +6.3% |
| In-house Swarm | 41.6% | **58.3%** | +16.7% |

**延迟优化**：减少高达 **4.5×** 推理延迟。

## 四、训练方法

### 4.1 多模态联合预训练

**核心发现**：早期融合 + 较低视觉比例优于晚期融合。

| 视觉注入时机 | 视觉:文本 | 视觉知识 | 视觉推理 | 文本知识 | 代码 |
|-------------|----------|---------|---------|---------|------|
| **早期 (0%)** | **10%:90%** | **25.8** | **43.8** | **45.5** | **24.8** |
| 中期 (50%) | 20%:80% | 25.0 | 40.7 | 43.9 | 24.0 |
| 晚期 (80%) | 50%:50% | 24.2 | 39.0 | 43.1 | 24.0 |

**训练阶段**：

| 阶段 | 数据类型 | Token 数 | 序列长度 |
|------|---------|---------|---------|
| ViT 训练 | alt text, caption, grounding, OCR | 1T | 4096 |
| 联合预训练 | 文本、知识、视频、OS 截图 | 15T | 4096 |
| 长上下文激活 | 高质量文本、长视频、长 CoT | 500B→200B | 32K→262K |

### 4.2 Zero-Vision SFT

**创新**：仅用文本 SFT 数据激活视觉和 Agent 能力。

**关键发现**：
- 所有图像操作通过 IPython 程序化代理
- 泛化到视觉接地任务（定位、计数、OCR）
- 添加人工设计的视觉轨迹**反而损害泛化**
- 原因：联合预训练已建立强大的视觉-文本对齐

### 4.3 联合多模态 RL

**跨模态迁移发现**：视觉 RL 提升文本性能

| 基准 | 视觉 RL 前 | 视觉 RL 后 | 提升 |
|------|-----------|-----------|------|
| MMLU-Pro | 84.7% | **86.4%** | +1.7% |
| GPQA-Diamond | 84.3% | **86.4%** | +2.1% |
| LongBench v2 | 56.7% | **58.9%** | +2.2% |

**联合 RL 范式**：按能力组织（非按模态），领域专家同时从纯文本和多模态查询中学习。

### 4.4 Toggle 算法

在推理时扩展和预算约束优化之间交替：

$$\tilde{r}(x,y) = \begin{cases} r(x,y) \cdot I\{ \frac{1}{K}\sum_i r(x,y_i) < \lambda \text{ 或 } |y_i| \leq \text{budget}(x) \} & \text{Phase 0} \\ r(x,y) & \text{Phase 1} \end{cases}$$

**效果**：输出 token 减少 **25-30%**，性能影响可忽略。

### 4.5 DEP 训练基础设施

**Decoupled Encoder Process (DEP)**：

```
阶段 1: 平衡视觉前向传播
  ├── 所有 GPU 复制视觉编码器
  ├── 根据负载均衡分配计算
  └── 丢弃中间激活，仅保留最终输出
       │
阶段 2: 主干训练
  ├── 主 transformer 前向和反向
  └── 充分利用纯文本高效并行
       │
阶段 3: 视觉重计算与反向传播
  ├── 重新计算视觉编码器前向
  └── 反向传播计算视觉梯度

效果：多模态训练效率达到纯文本训练的 90%
```

## 六、相比 K2 的关键创新

| 特性 | K2 | K2.5 |
|------|-----|------|
| 模态 | 纯文本 | **原生多模态**（文本+视觉） |
| 视觉编码器 | 无 | **MoonViT-3D** |
| 视频处理 | 不支持 | **支持，4× 时间压缩** |
| 上下文窗口 | 128K | **256K** |
| Agent 编排 | 顺序执行 | **Agent Swarm 并行** |
| 训练效率 | 纯文本优化 | **DEP，多模态达 90%** |

### 6.1 训练方法创新

1. **早期融合策略**：早期融合 + 低视觉比例优于晚期融合
2. **Zero-Vision SFT**：仅用文本 SFT 激活视觉能力
3. **联合多模态 RL**：按能力组织（非按模态）
4. **视觉 RL 提升文本**：MMLU-Pro +1.7%，GPQA-Diamond +2.1%
5. **Toggle 算法**：token 减少 25-30%
6. **Token 级裁剪**：缓解离策略发散

## 七、与竞品对比

**K2.5 领先领域**：
- Agent 搜索 (BrowseComp: 50.2% vs GPT-5.2 45.5%)
- 深度研究 (DeepSearchQA: 77.1% vs Claude 76.1%)
- 长视频理解 (LVBench: 75.9% vs Gemini 73.5%)
- OCR 理解 (OCRBench: 92.3% vs Claude 86.5%)
- 计算机使用 (OSWorld-Verified: 63.3% vs GPT-5.2 48.6%)

**GPT-5.2 领先领域**：
- 完美数学推理 (AIME 2025: 100%)
- 指令遵循 (AdvancedIF: 81.1% vs K2.5 75.6%)

**Claude Opus 4.5 领先领域**：
- 软件工程 (SWE-Bench Verified: 80.9% vs K2.5 76.8%)
- 知识问答 (SimpleQA Verified: 44.1% vs K2.5 36.9%)

**Gemini 3 Pro 领先领域**：
- 知识问答 (SimpleQA Verified: 72.1% vs K2.5 36.9%)

## 八、关键差异化优势

1. **开源策略**：首个开源万亿参数多模态 Agent 模型
2. **原生多模态**：图文联合优化，避免模态冲突
3. **Agent Swarm**：独特并行 Agent 编排，延迟减少 4.5×
4. **Zero-Vision SFT**：零视觉 SFT 激活视觉能力
5. **视觉 RL 跨模态增益**：视觉 RL 提升纯文本任务
