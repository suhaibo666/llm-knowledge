## B. 问题清单（严重在前）

1. [major] 24 §4.3：页面说「flush 成功后才 record_turn」，只在流式成立。非流式 `anthropic.py`/`openai.py::_respond` 是 `return web.json_response(...)`，body 要等 handler 返回后才发出，而 `record_turn` 在此之前已执行；只有 `_render_stream` 先 `await out.prepare`。修正：把保证限定为流式；CLI 是否流式标为依赖侧未核。
2. [major] 28 §3：mask 图不能重放算法。流程图只放位串；`get_batch` 的 `F.pad(mask,(prompt_length-1,1))` 平移和 qwen3_5 的字符→token 投影只写在正文；13 个位置是示意，与整改台账"真实模板算例"不符；答案 A 漏了 `<|im_end|>\n`（三种多轮 lane 都会训练它）。修正：生成 SVG token 网格，走完「完整 mask → response span → 平移后 mask」。
3. [major] 28 §6：缺长度包络。list 形式 prompt 在 `data.py::filter_long_prompt` 只告警不过滤（"Skipping max_length check for list prompt"）；`dp_schedule.py` 注明超长样本单独占一个 micro-batch 并允许超过 token 上限；全程无截断。修正：补边界与 OOM 风险。
4. [major] 23 §4：构造侧变体无枚举。`scripts/models/*.sh` 的 `--spec` 绑定 glm4、glm5（DSA）、minimax_m2、qwen3_5、qwen3_next，页面未交代；同属 GDN 选择的 `--qwen-gdn-backend`（fla|flashqla）未点名。修正：以 spec 绑定为依据列清单，写明各自归属页。
5. [major] 23 §5：只重放 GLU。`qwen3_next_hf_tensor` 用 `q.reshape(groups,qpg,2,head_dim)`，§5.4 漏了门控 ×2；EP 专家偏移（`_named_params_and_buffers_global`）、`hf_attention` 的 CP 两段重组都没用同一例子重放。
6. [major] 26 §4：mRoPE 推进规则 `current_position += max(h,w)//merge`（所以文本从 3 而不是 5 继续）没有解释；`_inject_vision_embeddings` 的「完整位置→feature 行→CP 局部索引」没有例子。
7. [major] 26：无成本账。每个 TP rank 复制一份 ViT；每个 CP rank 都对整批图像跑 ViT；CP 要 all-gather ids；processor 本地与 SGLang 各算一次。
8. [major] 24 §5.2：「若下一轮 prompt 把 A 改写为 A′」混淆两层。消息层改写先走 `_try_merge_assistant_rewrite`（单个生成叶且短于阈值时降级为仅路由），只有消息 dict 相等、token 不同才进入 drift 判断；这一层未重放。
9. [minor] 23 §9.2：`partition_stride` 断言只在 `all_gather_param`（VPP distributed 路径）。默认 Direct 路径 `all_gather_params_async` 只断言 `partition_dim is not None`（默认值为 -1，永远成立）；非 GLU 的 fc1 在默认路径上会被静默错拆。
10. [minor] 24 §8.1/§9.4：只有外层 `rollout_guard_sec` 返回 ABORTED。内层 `agent_time_budget_sec` 超时（exit code<0）后仍评分，并返回半棵树的 Samples。
11. [minor] 27 §5：heterogeneous 采样数不只是 passrate 口径错。`compute_pass_rate` 断言 `len==num_groups*group_size`，不整除时 logger 直接崩溃。
12. [minor] 26 §6：「累计 budget 4096」不准。未设 `rollout_max_context_len` 时，`_prepare_start_state` 的 budget = max_new_tokens − prompt 长度。
13. [minor] 28 §5：`--n-samples-per-prompt 1` 不在任何官方脚本里（默认值）；页面只引 4B 脚本，而 `run-qwen3.5-35B-A3B-sft.sh` 是唯一选 `qwen3_5` 的地方；4B-Base 实际用默认 `qwen` 类型。
14. [minor] 28 §6：「评估另用 27 的路径」有误导。SFT 脚本带 `--debug-train-only`，`RolloutManager.eval` 直接返回，评估是静默空操作。
15. [nit] 24 未写默认 fork_threshold=1024；27 说保存文件的 rollout id 带 `eval_` 前缀，实际只有路径带，dict 里仍是 int；23 §7 round-trip 测试覆盖 9 个 family，页面只描述 Qwen3-Next。
