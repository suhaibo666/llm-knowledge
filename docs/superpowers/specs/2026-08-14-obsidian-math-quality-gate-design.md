# Obsidian 数学公式质量门禁设计

## 1. 背景与问题

`llm-knowledge` 是以 Obsidian 为主要阅读端的 Markdown 知识库。当前 slime/vime 系列中同时出现 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]` 四类定界符；后两类虽然属于通用 MathJax/LaTeX 写法，却不是本仓库面向 Obsidian 的统一写法。部分公式还把多字母指标直接写成数学变量，例如 `accept\_rate`、`TP\_size`、`p_{train-old}`，导致斜体、减号语义或下划线显示不符合原意。

问题不只是已有页面需要修复，也缺少一个可重复执行的自检流程。仅靠文字规范无法阻止后续生成内容再次引入同类缺陷。

## 2. 目标与范围

本次交付包含三部分：

1. 整改当前 `wiki/02_engineering/04_posttrain_frameworks/slime/` 目录中的公式，包括 VIME 支持分析页。
2. 新增零第三方依赖的 Markdown 数学公式检查器，既可检查显式文件，也可检查 Git 变更文件。
3. 在仓库 `.agents/skills/` 中新增公式写作 skill，并按仓库现有兼容布局同步到 `.claude/skills/`；同时在 `CLAUDE.md` 中加入必须执行的公式自检要求。

不在本次范围内：批量重写整个知识库的历史公式、改变公式所表达的技术结论、引入 Markdown 渲染器或 Node.js 依赖、把启发式风格检查全部升级成提交阻断。

## 3. 仓库公式标准

### 3.1 定界符

- 行内公式统一为 `$...$`。
- 块级公式的起止 `$$` 必须各自独占一行。
- 新增或修改的文档不得使用 `\(...\)`、`\[...\]`。
- 代码围栏和行内代码中的示例不参与定界符检查。

### 3.2 数学语义与排版

- 多字母语义下标使用 `\mathrm{...}` 或 `\text{...}`，例如 `$C_{\mathrm{low}}$`，不能把 `low` 当作三个相乘的变量。
- 函数或指标名优先改写为数学符号并在正文解释；确需保留 API 名时使用 `\operatorname{...}` 或 `\texttt{...}`，不能写 `accept\_rate` 这类裸转义标识符。
- 条件概率和条件分布使用 `\mid`，绝对值使用 `\lvert...\rvert`，避免用间距错误且容易与 Markdown 表格冲突的裸 `|`。
- 多行推导使用 `\begin{aligned}...\end{aligned}` 对齐，避免依赖源码换行实现视觉结构。
- Markdown 表格单元格内只放短行内公式；块级公式移到表格外。

## 4. 自动检查器

新增 `tools/check_math.py`，公开以下能力：

- `check_text(text, path)`：检查一段 Markdown 并返回带文件、行号、等级、规则编号和消息的诊断。
- `check_file(path)`：读取单个 UTF-8 Markdown 文件并调用 `check_text`。
- `collect_changed_markdown(repo_root)`：合并工作区、暂存区和未跟踪文件中的 Markdown 变更。
- CLI 支持显式文件/目录与 `--changed`；默认仅错误导致非零退出，`--strict` 下警告也导致非零退出。

### 4.1 错误规则

- `MATH001`：代码之外出现 `\(`、`\)`、`\[` 或 `\]`。
- `MATH002`：块级 `$$` 未闭合。
- `MATH003`：排除常见货币写法后，单行行内 `$` 未成对。
- `MATH004`：提取出的公式花括号不平衡。
- `MATH005`：Markdown 表格单元格中出现块级公式，或表格公式中使用裸 `|`。

### 4.2 警告规则

- `MATH101`：块级公式和 `$$` 写在同一行，而不是让定界符独占一行。
- `MATH102`：`\text`、`\texttt`、`\mathrm`、`\operatorname` 之外出现 `\_`。
- `MATH103`：花括号下标中出现未用直立字体包裹的多字母语义名、斜杠或连字符。
- `MATH104`：普通公式中出现裸条件竖线 `|`。
- `MATH105`：块级公式单行过长且没有使用 `aligned`。

检查器只对高置信度结构问题默认阻断；风格启发式先作为警告，由文档作者在 `--strict` 自检中判断并修正。解析时必须忽略代码围栏与行内代码，并避免把 `$5.5M` 等货币文本误判为公式。

## 5. Skill 与仓库集成

新增 `writing-obsidian-math` skill。它在编写或修改包含 LaTeX/MathJax 公式的知识库 Markdown 时触发，内容包括：

- 仓库定界符和数学语义规范；
- 常见错误到正确写法的对照；
- 编辑后的人工检查清单；
- 显式文件自检与 Git 变更文件自检命令；
- 严格模式警告必须人工处理，不能为了通过检查器而改变公式数学含义。

`.agents/skills/writing-obsidian-math/` 是 Codex 使用位置；`.claude/skills/writing-obsidian-math/` 保持完全相同的内容，延续仓库已有双目录兼容约定。

## 6. 测试与验收

先写测试并确认在检查器不存在时失败，再实现最小检查器。测试至少覆盖：

- 非标准定界符、未闭合块公式和未闭合行内公式；
- 代码围栏、行内代码与货币文本不误报；
- 标准 `$...$` 和独占行 `$$` 通过；
- `\texttt{accept\_rate}` 中的转义下划线允许，裸 `accept\_rate` 给出警告；
- Markdown 表格中的裸竖线给出错误；
- `.agents` 与 `.claude` 两份 skill 内容一致。

最终必须运行单元测试、对本次修改的 slime/vime 页面执行严格公式检查、执行仓库链接检查，并运行 `git diff --check`。历史页面不纳入本次强制整改，因此不会把全库遗留问题作为本次交付阻塞项。
